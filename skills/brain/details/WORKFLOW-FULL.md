# Zettelkasten 完整工作流（4 阶段 + 1 维护）

> 核心 .md 文件只留 1 句话索引，详情见本文件。

---

## 阶段 1：检索优先（每次回复前）

**触发**：每次用户提问

**动作**：
1. 用 `zk_search_notes` 搜索相关知识（2-5 关键词）
2. 有命中则在回复中引用笔记内容 + 告知 ID

**例外**：用户明确说"不用查"、"直接回答"

---

## 阶段 2：知识健康度检查（每周或用户询问时）

**触发**：用户问"知识库状况"、"僵尸笔记"、"笔记活跃度"

**动作**：
1. `zk_glow_ranking` 获取发光度分布
2. `zk_find_zombies` 列出候选
3. `zk_get_archive_log` 看最近归档操作
4. 给出维护建议（归档/补链/激活）

---

## 阶段 3：智能记录（识别价值信息）

**触发条件**（满足任一）：
- 用户说"记下来"/"保存"/"记录"
- 用户分享新工具/新方法/新概念
- 用户总结某个领域的知识
- 对话产生了有价值的结论或决策
- 用户纠正了你的错误理解

**动作**：
1. `zk_create_note` 创建原子笔记
2. 标题 5-15 字
3. Markdown 格式，保持原子化（一个笔记 = 一个想法）
4. 标签：从内容提取 2-5 关键词
5. 置信度：
   - 用户确认事实 = 0.8+
   - 用户经验分享 = 0.7
   - 推测/常识 = 0.5
   - 临时想法 = 0.3

**回复模板**：
```
📝 已保存到知识库
标题：[标题]
ID: [ID]
标签: [tag1, tag2]
置信度: [score]
```

---

## 阶段 4：关联构建（**只建议，不执行**）

**触发**：创建新笔记后

**动作**：
1. 搜索可能相关的已有笔记
2. 语义关联度 > 0.6 时 **建议用户** 建立链接
3. 链接类型（供建议用，非 AI 直接调用）：
   - `related` — 一般关联
   - `supports` — 支持/佐证
   - `extends` — 扩展/深化
   - `contradicts` — 矛盾/修正

**重要**：AI 助手**只建议，不执行建链**。链接由 zk nightlyDistill 自动维护。

---

## 阶段 5：归档管理（知识库维护）

**触发**：
- 用户说"归档这条笔记"
- 用户问"这条笔记是不是该归档了"
- 发现笔记已过时且无人引用

**动作**：
1. `zk_archive_note` 移入 archive folder
2. 告知用户归档不影响数据
3. 恢复用 `zk_unarchive_note`

**回复模板**：
```
📦 已归档
笔记: [标题]（ID: xxx）
说明: 归档数据保留，可通过 zk_search_archived 专门检索
```
